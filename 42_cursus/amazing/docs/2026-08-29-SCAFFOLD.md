3. Coordinates: (col, row)

Internally everything is (col, row) — column first, the same order the
config file uses. The grid is indexed grid[col][row].
Nothing is ever converted, anywhere.

  EXIT=19,14    in the config file
  (19, 14)      in the code
  19,14         in the output file

19 is ALWAYS the column, 14 is ALWAYS the row. It is the bottom-right
cell: column of index 19 (the twentieth) and row of index 14 (the
fifteenth).

The names are col and row everywhere, never x and y: there is then
nothing left to remember about which one comes first.

grid is a list of COLUMNS, not of rows: grid[col] is that column,
HEIGHT cells tall. That way the order of the two indices is always the
same as the order of the coordinates.

The only place that thinks in rows is writing the output file, which
the subject wants one line per row of the grid:

  for row in range(height):
      line = "".join(digit(grid[col][row]) for col in range(width))

That is not a conversion: it is only the order in which the grid is
traversed.

Wall bits (1 = closed):

  bit 0 = N = (col, row - 1)
  bit 1 = E = (col + 1, row)
  bit 2 = S = (col, row + 1)
  bit 3 = W = (col - 1, row)

row grows DOWNWARDS, as on screen: that is why N is row - 1.
